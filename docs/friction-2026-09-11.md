## Trust and limits

Test runners and package scripts use the existing project-code trust boundary used by `bun test` and conventional Bun gates. Recognition does not prove that their bodies or dependencies are safe. It permits an intentional project check and does not extend AST inspection to arbitrary script files.

The new runner paths reject unverified startup variables and working-directory changes. Manifest reads are limited to one MiB, require a regular file and valid UTF-8/JSON, and close the descriptor on every path. Tripwire does not import a manifest or execute a script to classify it. These observations cannot prevent concurrent changes between policy evaluation and execution.

Conventional Bun gate names retain their prior policy. Additional names and `--cwd` forms require a manifest in the selected directory. Parent-directory discovery, shell `cd` propagation, and arbitrary runtime wrappers need further work.

The claim that `--no-sync` fixed Python contract export is incomplete: a later recorded `uv run --locked --no-sync python scripts/export_openapi.py` call was also denied. This flag prevents environment synchronization; it does not expose a script body to the AST inspector. File-backed exports retain the existing review boundary.

Other refusals included Python merge-repair loops, regex callbacks, unsupported modules, zsh glob qualifiers, Git ref writes, conflict-side checkout, and stash deletion. The Python cases need more bounded semantic support. The Git operations can discard or replace work and retain their protections. The zsh case needs shell-specific syntax support.

# Mise startup inspection

Tripwire checks what `mise exec` can add before inspecting inline interpreter code. It reads configuration and backend metadata without running mise, plugins, templates, or interpreters. The result is a typed success or a failure carrying a reason, which follows the forwarded invocation into its denial message.

The original implementation rejected every inherited `__MISE*` variable, every `[settings]` table, and every per-tool backend metadata file. These are ordinary parts of an activated mise installation. Tests removed the activation variables and supplied minimal configs without installed metadata, so their allow cases missed these failures. Removing activation variables alone still left the global settings and backend metadata failures. A fresh process with an empty environment and an isolated config did allow the minimal fixture during reproduction.

## Activation state

This audit uses [mise v2026.9.12](https://github.com/jdx/mise/tree/v2026.9.12). The important distinction is between `PRISTINE_ENV`, used to compute changes, and the additions returned by `Toolset::env_with_path_and_removals`. On Unix, [`exec_program`](https://github.com/jdx/mise/blob/v2026.9.12/src/cli/exec.rs) removes specified keys and sets those additions in the existing process environment. It does not replace that environment with `PRISTINE_ENV`. The spawn path similarly applies the additions and removals.

| Inherited variable                                       | Use in mise; why accepted                                                                                                                                                                                                                                                                                                                                 |
| -------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `MISE_SHELL`                                             | Selects a shell type for shell integration; direct `exec -- program` does not evaluate its value as source.                                                                                                                                                                                                                                               |
| `__MISE_DIFF`                                            | Decoded as compressed MessagePack by `env.rs` and `env_diff.rs`; reconstructs pristine values and removes previously inserted PATH entries. It is data, not shell source. Reconstructed arbitrary values are not copied wholesale into exec's additions. Config templates and env directives that could use those values to execute code remain rejected. |
| `__MISE_ORIG_PATH`                                       | Saved PATH for activation/deactivation restoration in `hook_env.rs`; direct exec constructs its child PATH using the toolset.                                                                                                                                                                                                                             |
| `__MISE_SESSION`                                         | Hook session data used by `hook_env.rs` to track changes and decide whether a shell hook needs to refresh. Direct exec does not run hook-env.                                                                                                                                                                                                             |
| `__MISE_ZSH_ACTIVATE_ENV`, `__MISE_ZSH_ACTIVATE_PATH`    | Shell-side snapshots used by the Zsh activation script to skip a redundant initial refresh.                                                                                                                                                                                                                                                               |
| `__MISE_ZSH_CHPWD_RAN`, `__MISE_ZSH_PRECMD_RUN`          | Shell-hook scheduling state; not exec configuration.                                                                                                                                                                                                                                                                                                      |
| `__MISE_BASH_CHPWD_RAN`, `__MISE_BASH_SKIP_FIRST_PROMPT` | Bash's equivalent hook scheduling state.                                                                                                                                                                                                                                                                                                                  |
| `__MISE_EXE`, `__MISE_FLAGS`, `__MISE_HOOK_ENABLED`      | Bash activation wrapper variables. The mise executable's direct exec path does not consume them as commands or flags.                                                                                                                                                                                                                                     |
| `__MISE_LAST_UNTRUSTED_CONFIG_WARNING_KEY`               | Suppresses repeated shell-hook trust warnings; does not grant config trust or select executable behavior.                                                                                                                                                                                                                                                 |

See [`shell/`](https://github.com/jdx/mise/tree/v2026.9.12/src/shell), [`hook_env.rs`](https://github.com/jdx/mise/blob/v2026.9.12/src/hook_env.rs), [`env.rs`](https://github.com/jdx/mise/blob/v2026.9.12/src/env.rs), and [`toolset_env.rs`](https://github.com/jdx/mise/blob/v2026.9.12/src/toolset/toolset_env.rs). Fish, Nushell, Elvish, PowerShell, and Xonsh use the shared shell/diff/session names; there is no blanket allowance for hypothetical shell-specific names. Internal execution controls such as `__MISE_SCRIPT`, `__MISE_SHIM`, and `__MISE_ENV_CACHE_KEY` remain unsupported and identify themselves in denials.

An inherited `PYTHONPATH`, `NODE_OPTIONS`, or similar variable is part of the same baseline a plain interpreter receives. Its presence alone does not block mise. Config or dotenv additions of these variables still block, even if their value matches the inherited value. Submitted mutations of activation/discovery state also block; inherited bookkeeping approval cannot authorize a shell command to replace it.

## Settings and backend identity

Supported settings are deliberately explicit: boolean `verbose`, `quiet`, `yes`, `color`, boolean `ruby.compile`, and `idiomatic_version_file_enable_tools` containing plain tool names. Other settings identify the unsupported key. Templates are rejected throughout config, including otherwise inert task and settings tables.

Mise's [`settings.rs`](https://github.com/jdx/mise/blob/v2026.9.12/src/config/settings.rs) uses `ruby.compile` to choose installation behavior. It does not supply interpreter startup source. Idiomatic version discovery in [`config/mod.rs`](https://github.com/jdx/mise/blob/v2026.9.12/src/config/mod.rs) can consult enabled tools' backends, so every enabled name is included in plugin/backend checks, even when it is absent from `[tools]`. Built-in registry/core readers parse version data; plugin readers are not authorized by this setting.

[`toolset/install_state.rs`](https://github.com/jdx/mise/blob/v2026.9.12/src/toolset/install_state.rs) supports consolidated `.mise-installs.toml`, per-tool `.mise.backend.toml`, legacy JSON (`id`), and legacy text (short name followed by full backend name). Tripwire checks every present format conservatively, including shadowed metadata. It accepts an explicit matching core backend with no backend options and rejects plugins, mismatched identities, and malformed metadata. File presence by itself no longer means an unsafe backend.

## Regression evidence

`test/mise-process.test.ts` launches `src/main.ts --tripwire-hook` with Bun in a fixture working directory. The child never loads the test preload. HOME, config, data, and system paths stay in the fixture; PATH has the shape of an activated installation. A valid serialized activation diff and an inherited startup variable exercise the real environment boundary. Global `[tools]` and `[settings]` plus core backend metadata allow `print(1)`; destructive inline code and a config-added `PYTHONPATH` deny. The original implementation fails the allow assertion.

`test/mise-startup.test.ts` additionally checks activation names across shells, all metadata formats and their plugin twins, unsupported variables, and config/key/parser/plugin denial reasons. Parser diagnostics identify the file without echoing config contents.

## Idiomatic version files and inspector contracts

The filename table in `src/lib/mise/idiomatic.ts` comes from the complete [v2026.9.12 registry](https://github.com/jdx/mise/tree/v2026.9.12/registry). In [`backend/mod.rs`](https://github.com/jdx/mise/blob/v2026.9.12/src/backend/mod.rs), `idiomatic_filenames` combines the registry entries with backend-specific names. The default backend implementation contributes no names; asdf and vfox can consult plugins and remain unverified. `load_idiomatic_filenames_for_tools` in [`config/mod.rs`](https://github.com/jdx/mise/blob/v2026.9.12/src/config/mod.rs) selects enabled tool IDs.

Tripwire accumulates enabled tools conservatively across inspected settings and checks their registered filenames in the same lexical and resolved ancestors, with the same ceilings, as local configuration. Only a trimmed plain version accepted by `version()` is allowed. This includes checking `.nvmrc`, `.node-version`, `.python-version`, `.python-versions`, `.ruby-version`, and every other registry entry. Structured files such as `package.json`, `Gemfile`, `go.mod`, and `rust-toolchain.toml` are discovered but their structured contents are unsupported. A denial identifies the filename. Enabled non-core tools without installed plugins are permitted; existing plugin/backend checks still apply to all enabled tools.

Shell environments and invocations carry one required startup state: direct, checked, or unverified with a reason. Every copy and join uses the same join function, retaining the most restrictive state and first unverified reason. The checked-state context guard retains its existing command, redirect, and assignment rules.

The wrapper spec owns the startup result and supplies parsed operands and option values to mise. Mise validates tools and profiles without reparsing argv. Its assertion validators return no value and throw `MiseInspectionError` for expected inspection failures. Other exceptions fail closed with an internal mise inspector error message without exposing exception details.

# September 2026 transcript audit follow-up

## 0.11.0 follow-ups: environment, callbacks, syntax, and test isolation

The package remains **0.11.0**. Changes were committed on `main`; nothing was pushed, tagged, published, or installed globally. Lint, formatter, and TypeScript configuration files were unchanged.

### 1. Hermetic tests

The test preload creates a private home, work directory, temporary directory, and Bun executable link. It clears inherited mise/XDG/Tripwire overrides and interpreter preload options. Policy calls use a fictional default cwd; filesystem tests supply their own explicit fixture directories. Source subprocesses and the Pi build locate entries through `import.meta.url`, independently of the launch directory.

Changing `HOME` alone was insufficient: Bun 1.4.2's `os.homedir()` retained the original home. The preload supplies explicit home and temporary-directory functions before application modules load. Temporary roots are canonicalized so macOS `/var` symlinks cannot change home comparisons.

Removed wall-clock assertions from recursive-glob, shared-data, and evaluation-budget tests, and removed the evaluation test's CPU-duration threshold. Budget tests assert the reported budget gap. Recursive globs use a fictional home; bounded glob tests create their own matches. No test glob enumerates the developer's home, `~/dev`, or shared `/tmp` contents.

Failures exposed during isolation:

- **`fd-prefixed redirect does not become an rm target`** depended on whatever `/tmp/foo-*` happened to match. It now creates a matching file in a private directory.
- **`reads local JSON as data and retains protected-path checks`** depended on the checkout's `package.json`. It now writes a fictional manifest and passes its fixture cwd explicitly.
- **`blocks tar -xf foo -C $HOME`** exposed a logical-versus-canonical temporary-home mismatch on macOS. Canonical fixture roots remove it.
- The new mise global-dotenv and safe-wrapper tests exposed Bun's cached home and the need for an explicit existing cwd. They now use the isolated environment and explicit fixtures.

The original wall-clock failures were not reproduced before their assertions were removed; those assertions tested host scheduling rather than the inspector's budget behavior. Development assertion updates retain the original security checks: a precise callback can now produce a dangerous operation without an analysis gap, so the literal case asserts a policy denial and the opaque case still asserts a gap.

### 2. Static mise startup inspection

The reference is the installed **mise 2026.9.12**, its [configuration documentation](https://mise.jdx.dev/configuration.html), and the matching source for [config discovery](https://github.com/jdx/mise/blob/v2026.9.12/src/config/mod.rs), [early configuration](https://github.com/jdx/mise/blob/v2026.9.12/src/config/miserc.rs), and [config roots](https://github.com/jdx/mise/blob/v2026.9.12/src/config/config_file/config_root.rs).

`mise exec`, `mise x`, cwd options, explicit core-tool versions, and environment profiles share the same check. Discovery covers local and parent configs, local variants, `conf.d`, `.miserc.toml`, global/system files, XDG and supported `MISE_*` path/filename overrides, and `.tool-versions`. TOML is parsed by Bun. Dotenv paths use mise's config root, including the home root for global configuration.

Plain core-tool version selections and inert environment values are accepted. Startup variables share the interpreter-startup set. Parse/read failures, unknown cwd, startup-variable changes, hooks, unchecked env directives, plugins, tool options, unknown settings/overrides, and unverified backend metadata deny. Templates are rejected throughout decoded TOML keys and values, including Unicode-escaped delimiters and task fields. Plain tasks remain inert. No mise executable, plugin, config template, or submitted command runs during inspection.

Discovery is conservative: inactive `conf.d` fragments and overlapping layers are also checked rather than using precedence to excuse an unsafe declaration. Unsupported configuration stays denied. Another submitted command that can change configuration prevents authorization of a mise-dependent inline interpreter. The guard follows the affected invocation, so a separate mise command does not taint unrelated bare Python/JavaScript blocks.

### 3. Literal callbacks

Precise lists of at most 128 items supply their real items, in order, to JavaScript `map`, `filter`, `forEach`, `some`, `every`, `find`, `flatMap`, and `reduce`, plus Python `map`, `filter`, `sorted(key=)`, and comprehensions. Reducers carry their accumulator between invocations. Opaque receivers retain unknown-count analysis.

Mutation through a receiver alias or captured container cannot preserve stale precision. Known inner lists retain unknown-repetition safeguards when an enclosing loop has an unknown count. Python string `find` remains an ordinary string operation. Fictional allow/deny twins cover every added callback form, ordering, reducers, mutation, and the item limit.

### 4. Syntax diagnostics

The parser reports the first syntax error in source order with its language, one-based line/column, and an excerpt of at most 48 source characters. Literal backslash-n near the error explains that single shell quotes preserve two characters and recommends a heredoc. Unexpected parser or analyzer-construction exceptions deny with an internal-inspector-error message, without exception text or the complete source.

Bun transpilation needs special care: its documented macro support can execute code during transformation. Literal source without imports is inspected; opaque file-derived transpiler input remains denied. [Bun transpiler documentation](https://bun.sh/docs/runtime/transpiler). Python also documents parent-package import during dotted module discovery. [Python importlib documentation](https://docs.python.org/3/library/importlib.html#importlib.util.find_spec).

## Boundaries retained

There are no remaining rows classified merely as “Not yet supported.” The tables above distinguish implemented forms from specific unproved effects, invalid inputs, absent replay filesystem state, and existing policy restrictions. This does not claim that every possible Python or JavaScript construct is modeled.

Uninspected module execution, dynamic imports, reflection/eval, unknown call targets, implicit class hooks, runtime environment mutation, unproved filesystem-derived operands, unverified startup/remote contexts, and analysis-budget exhaustion remain fail closed. These hooks do not establish runtime filesystem containment.
